# M9 字段与工作流实用性增强 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 9 大模块从「字段太简单、不具备实用性」提升到 PMBOK 第六版最佳实践水平，并新增第 10 大模块「团队管理」（对标 PMBOK Project Resource Management）。当前 9 模块共 123 字段、6/9 工作流为三节点极简流、auto 自动节点 0/9 缺失；M9 目标补全约 90 字段 + 新增 team 模块约 58 字段 + 重构工作流，使字段总数达到 ~270、EVM 闭环可算、WBS 结构化、依赖类型完整、状态机与工作流对齐、团队管理覆盖 RACI/技能矩阵/绩效评估/培训建设全闭环。

**Architecture:** 保持 EAV 数据模型不变。所有改动集中在三类元数据文件：`schema.yaml`（字段定义）、`seed.yaml`（字典/种子）、`workflows/*.yaml`（声明式工作流）。插件 `InitPMocker()` 钩子启动时灌入 EAV 元表，无需改业务代码。前端表单适配留待验证后按需调整（M9 聚焦元数据层）。

**Tech Stack:** YAML（schema/seed/workflow）、Go 1.22+（EAV 加载器）、gin-vue-admin v3.0.0、SQLite

## Global Constraints

- 文件路径统一：`gva/server/plugin/pmocker_<mod>/pmocker/{schema,seed}.yaml` + `workflows/*.yaml`
- 字段 `field_key` 用 snake_case，`data_type` 取值：`string|text|int|decimal|date|datetime|bool|enum|ref|json`
- `enum` 字段必须在 `options` 列全可选值；`ref` 字段必须指明 `ref_to` 实体类型
- 基线字段统一命名：`baseline_version`(string) + `baseline_date`(date) + `baseline_by`(ref→sys_users)
- 新增字典统一放对应模块 `seed.yaml` 的 `dictionaries` 节，`dict_code` 用 `pm_<mod>_<name>` 前缀
- 工作流节点类型必须用：`start|approval|auto|task|end`；`auto` 节点必须有 `handler` 指向内核函数
- schema 的 `states` 必须与 workflows 的流转状态一一对应，禁止「死状态」（schema 定义了但工作流不可达）
- 幂等：`InitPMocker()` 钩子用 `FirstOrCreate`，重复初始化不产生重复记录
- 改动后必须重建默认镜像 `pmbok6-hybrid.pmi` 才能在实例中生效

### Task 13: 插件自动发现注册（T13）

**Problem:** 新增 PMocker 业务插件需要同步修改两处硬编码代码：
- `images/pmbok6-hybrid/build.go` 的 `pluginDirs` 字符串数组（容易遗漏，导致镜像缺失插件）
- `gva/server/plugin/pmocker_register.go` 的空白导入数组（容易遗漏，导致插件无法被 gva 加载）
- 容易出现「代码写了但镜像没包含」或「镜像包含了但二进制没导入」的不一致 bug

**Goal:** 实现零硬编码的插件自动发现机制，新增插件只需一条 `go generate ./plugin/` 命令即可生效。

**Files:**
- Modify: `images/pmbok6-hybrid/build.go`（`discoverPlugins()` 函数）
- Create: `gva/server/plugin/gen_pmocker_register.go`（`//go:build ignore` 生成器）
- Regenerate: `gva/server/plugin/pmocker_register.go`（由生成器产出，含 `//go:generate` 指令）

**Interfaces:**
- Produces: build.go 自动扫描 pmocker_* 目录；pmocker_register.go 由 go:generate 自动生成；新增插件后无需手动编辑任何「插件清单」代码。
