# PMocker M1 骨架阶段实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 搭建 PMocker 单仓骨架（go.work + gva subtree + CLI 框架），推送到 GitHub pmocker-io/pmocker 仓库，gva 原生可启动、`pmocker --version` 可运行。

**Architecture:** 单仓多模块。`go.work` 声明 cli/gva/server/pkg 三个 Go 模块。gva 通过 `git subtree` 从 gin-vue-admin main 分支拉入 `gva/` 目录，保持 gva 原始 module path 不变（`github.com/flipped-aurora/gin-vue-admin/server`）。PMocker CLI 用 Cobra 框架，仅实现 `--version` 和命令树骨架。

**Tech Stack:** Go 1.24 + Cobra（CLI）；gin-vue-admin v3（subtree）；Git Subtree（上游同步）；GitHub（远程仓库）

## Global Constraints

- Go 版本：1.24.0+（gva go.mod 要求 go 1.24.0）
- gva module path 保持不变：`github.com/flipped-aurora/gin-vue-admin/server`
- PMocker 模块 path：`github.com/pmocker-io/pmocker/cli` 和 `github.com/pmocker-io/pmocker/pkg`
- GitHub 账号：pmocker-io（已创建）
- gva 插件 Plugin 接口签名：`Register(group *gin.Engine)`（不是 RouterGroup），位于 `server/utils/plugin/v2`
- 插件通过 `init()` 调用 `plugin.Register(Plugin)` 自动注册，`server/plugin/register.go` 用空白导入触发
- 不修改 gva 原始文件（subtree pull 时不冲突）
- 当前工作目录：d:\Dev\pmocker（已 git init，已有需求文档.MD 和 .gitignore）

## gva 插件机制实测（用于后续 M2/M3）

经查阅 gva main 分支源码，实际插件机制如下：

**Plugin 接口**（`server/utils/plugin/v2/plugin.go`）：
```go
type Plugin interface {
    Register(group *gin.Engine)  // 注意：是 *gin.Engine 不是 *gin.RouterGroup
}
```

**注册器**（`server/utils/plugin/v2/registry.go`）：
```go
func Register(p Plugin)        // 在插件 init() 中调用
func Registered() []Plugin     // 返回所有已注册插件
```

**插件 init 模式**（以 announcement 为例）：
```go
package announcement

import (
    "context"
    "github.com/flipped-aurora/gin-vue-admin/server/plugin/announcement/initialize"
    interfaces "github.com/flipped-aurora/gin-vue-admin/server/utils/plugin/v2"
    "github.com/gin-gonic/gin"
)

var _ interfaces.Plugin = (*plugin)(nil)
var Plugin = new(plugin)
type plugin struct{}

func init() {
    interfaces.Register(Plugin)
}

func (p *plugin) Register(group *gin.Engine) {
    ctx := context.Background()
    initialize.Api(ctx)
    initialize.Menu(ctx)
    initialize.Dictionary(ctx)
    initialize.Gorm(ctx)
    initialize.Router(group)
}
```

**触发方式**（`server/plugin/register.go`）：
```go
package plugin
import (
    _ "github.com/flipped-aurora/gin-vue-admin/server/plugin/ai"
    _ "github.com/flipped-aurora/gin-vue-admin/server/plugin/announcement"
    _ "github.com/flipped-aurora/gin-vue-admin/server/plugin/auto"
)
```

> **需求文档修正项**（M2 时落实）：需求文档 11.3 节 plugin.go 示例中 `Register(group *gin.RouterGroup)` 应改为 `Register(group *gin.Engine)`，且不需要 `CreatePlugin()` 工厂函数，改用 `init()` + `interfaces.Register()` 自动注册模式。PMocker 的 `InitPMocker()` 钩子在 `Register()` 方法内调用。

# PMocker

> Docker for Project Management Systems

PMocker 将项目管理系统封装为可分享的 `.pmi` 镜像，一条命令启动完整的项目管理系统。

## 快速开始

```bash
# 构建 CLI
make build-cli

# 启动默认 PMBOK 项目管理系统
./cli/pmocker.exe run --image pmbok6-hybrid.pmi -p 8080
```

## 三层抽象

| 概念 | 说明 | Docker 类比 |
|------|------|-------------|
| **PMI 镜像** | 项目管理系统模板 | Docker 镜像 |
| **PMSystem** | 运行中的 PM 系统实例 | Docker 容器 |
| **项目** | PMSystem 内管理的项目数据 | 容器内应用数据 |

## 项目结构

```
pmocker/
├── cli/       # PMocker CLI (Go + Cobra)
├── gva/       # gin-vue-admin v3 (Git Subtree)
├── pkg/       # 共享库 (EAV/OCI/Workflow/RBAC)
├── docs/      # 文档
└── go.work    # Go Workspace
```
